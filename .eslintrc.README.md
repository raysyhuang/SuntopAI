# Why these ESLint rules are set the way they are

`next lint` had no config and no eslint dependency, so it dropped into an
interactive setup wizard and exited. Nothing was gating lint.

**`@next/next/no-page-custom-font` — off.** The rule warns that a custom font
added in a component only loads for one page. Ours is the Noto Serif SC link in
the root layout's `<head>`, which applies to every page; the rule predates the App
Router and misreads it. See the note in `src/app/layout.tsx` for why that font is
loaded from Google rather than through `next/font`.

**`@next/next/no-img-element` — off for services and platform only.** Those pages
use native `<img>` with `priority` on their largest images, which CLAUDE.md records
as a deliberate LCP decision. Everywhere else the rule still applies, so a new
`<img>` outside those two pages is still flagged.

The `files` globs deliberately do not spell out `src/app/[locale]/...`. Square
brackets are a character class in a glob, so `[locale]` matches one character from
`l o c a e` and the override silently matches nothing.

**`jsx-a11y/alt-text` — error, not warning.** This site is image-led now. A missing
alt is a defect, not a suggestion.
